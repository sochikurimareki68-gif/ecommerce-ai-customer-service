# 对话流设计文档（六路条件判断版）

> 基于知识库设计 6 路条件判断对话流，使用扣子选择器节点（自带 LLM 意图识别）
> 对话流名称：customer_service_workflow

---

## 一、为什么用对话流而不是工作流

| 维度 | 工作流 | 对话流（本项目采用） |
|------|--------|-------------------|
| 会话记忆 | 无状态，每次独立执行 | **绑定一个会话，可读取历史消息** |
| 模型节点读历史 | 不支持 | **支持**，需在节点「输入」区打开「会话历史」开关（本项目 7 个节点均已开启） |
| 用户界面 | 支持布局/展示组件 | 支持 AI 对话组件 |
| 发布渠道 | 仅 API / 商店 / 模板 | **API&SDK、小程序、社交渠道、商店、模板** |
| 角色配置 | 不支持 | **支持**（角色名称、头像、开场白、音色等） |

**选择对话流的理由**：客服是典型的多轮对话场景，对话流原生支持多轮记忆，且发布渠道更广。两者可互转（资源库 → 操作 → 切换为对话流/工作流）。

> **注意**：对话流的「会话记忆」不是自动生效的。智能体「对话设置」里的「携带上下文轮数」（本项目设为 10）只是上限，每个大模型节点还必须在自己「输入」区打开「会话历史」开关，模型才会真正读到历史消息。本项目意图识别 + 6 个回复节点已全部开启。

> 迁移方式：在资源库找到该工作流 → 操作列 → **切换为对话流**。转换后开始节点会自动新增 `USER_INPUT` 和 `CONVERSATION_NAME` 两个预置参数。

### 智能体的两种模式

对话流创建好后，智能体有两种接入方式：

| 模式 | 行为 | 特点 |
|------|------|------|
| 单 Agent（自主规划模式） | 大模型先判断是否调用对话流，再读取返回值组织语言 | 灵活，但每次多一轮规划，响应更慢（实测业务咨询约 27s） |
| **单 Agent（对话流模式）** | 每轮对话直接执行绑定的对话流，参数 `USER_INPUT` 自动传入 | 无规划层、更快（实测约 12s），输出形态直接决定用户看到的内容 |

本项目最终采用**对话流模式**。注意：该模式下对话流输出会原样透传给用户，因此结束节点必须用「返回文本」（见第七章）；同时智能体人设中的"处理规则"不再参与消息分发，全部分支逻辑都由对话流承担。

## 三、开始节点（对话流专属）

对话流的开始节点自带两个不可删除的预置参数：

| 变量名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `USER_INPUT` | String | 是 | 用户在对话流中输入的原始内容 |
| `CONVERSATION_NAME` | String | 是 | 对话流绑定的会话，用于记录对话历史 |

> 转换前工作流遗留的自定义参数 `user_message` 会保留，但**非必填**。为避免取到空值，本项目将所有下游节点统一改绑到 `USER_INPUT`。

## 四、意图识别节点（扣子选择器节点）

扣子的选择器节点自带 LLM 意图识别功能，无需单独的 LLM 分类节点 + Switch 节点。

### 输入
```
query = {{USER_INPUT}}
```

### 系统提示词
```
你是优眠家居客服的意图识别器。请根据用户消息判断属于以下哪类意图：商品咨询、洗护指南、物流发货、退换售后、优惠活动、其他。
```

### 6 条意图匹配选项

| 选项 | 填写内容 |
|------|---------|
| 选项1 | 用户咨询商品材质、尺寸、颜色、款式、价格、推荐、对比等商品相关问题 |
| 选项2 | 用户询问床品清洗、保养、晾晒、缩水、起球等洗护方式问题 |
| 选项3 | 用户询问发货时间、快递公司、运费、包邮、到货时间等物流问题 |
| 选项4 | 用户要求退货、换货、退款、维修、投诉等售后服务问题 |
| 选项5 | 用户询问满减、优惠券、折扣、会员、积分、活动等优惠问题 |
| 选项6（默认） | 其他意图 |

> 该节点已开启「会话历史」，多轮追问时"那红色的呢""多少钱"这类省略主语的问句也能正确分类。实测「天丝床品怎么洗」→「那纯棉的呢」可正确落入洗护分支。

## 五、各分支详细设计

各分支的 LLM 节点均通过「技能」挂载知识库，检索与生成在同一个节点内完成，无需单独的知识库检索节点。6 个回复节点的「输入」区均已打开「会话历史」，与智能体「携带上下文轮数 10」配合，支持指代句与省略句追问。

### 分支④ 退换售后

**LLM 生成回复节点**
- 节点名称：`退换售后回复`
- 技能：床品客服FAQ + 优眠商品目录
- 输入：`input = {{USER_INPUT}}`
- 系统提示词：
```
你是优眠家居的电商客服，负责退换货与售后咨询。请严格依据知识库中的退换货政策回答，
不编造政策、时效、费用或赔偿方案。

【回答顺序】
1. 先直接回答用户问的事：给结论或流程；
2. 信息不足时，先给通用规则/流程，再在末尾追问最多 1 个问题；
3. 不允许只反问而不回答。

【必须掌握的口径】
- 7天无理由条件：商品未使用、未洗涤、未拆吊牌（试铺不算使用）；原包装完整、配件齐全、
  不影响二次销售；内衣、枕芯等贴身用品与定制商品（非质量问题）不支持。
- 7天无理由起算：以签收日期为第 1 天。用户问"怎么算时间"时按此说明，并提醒保留签收记录。
- 退货流程：订单页点击"申请售后"并选择退货 → 填写原因、上传商品照片 → 客服审核（通常 2 小时内）
  → 寄回商品并填写快递单号 → 仓库签收验货后 1-3 个工作日原路退款。
- 换货：流程同上，申请时备注要换的款式/颜色/尺码；仓库验货后 24 小时内发出；有差价需补/退差价。
- 运费：7天无理由由买家承担寄回运费；质量问题由卖家承担来回运费；漏发/错发由卖家承担。
- 质量问题：破洞、撕裂、缝线脱落、拉链损坏、与详情页明显不符的色差等，可免费退换。
- 投诉、情绪激烈、要求赔偿，或知识库没有依据：先安抚，再引导回复"转人工"，不要自行承诺赔偿。

【表达要求】
- 用"亲~"开头，语气温和、简洁；
- 用短句和数字步骤，不用表格、Markdown、代码块；
- 不要提及"知识库""FAQ 编号""规则来源"等内部信息；
- 流程类回复控制在 300 字以内，只给当前需要的信息；
- 结尾固定一句："如需人工帮助，回复'转人工'即可"。
```
- 用户提示词：`用户消息：{{input}}`

> 评测记录（2026-10-12）：R01「退货流程是什么？」、R03「7天无理由怎么算时间？」两条用例中模型只反问用户、未给出任何流程，导致关键信息未命中（见 eval/report.md 第三章）。上面的「回答顺序」「必须掌握的口径」即针对此问题的提示词强化，属于平台侧分支④的配置项，**需在扣子后台更新并重新发布才会生效（只保存不发布，API 仍调用旧版本）**。

- 用户提示词：`用户消息：{{input}}`

> ⚠️ **为什么问候语放在兜底分支**：意图识别的 6 条选项都是业务意图，打招呼（"你好""在吗"）会落到默认的兜底分支。若兜底节点也答"我不属于任何一类"，用户第一句话就会感到被拒。因此在兜底节点内补齐问候语处理，让"你好"也能得到自然、亲切的开场回复。
>
> 实测：「你好」→ 返回开场白（9.3s）「转人工客服」→ 返回转人工话术（11.6s），均正确。

## 六、代码节点（合并+格式化）

### 处理逻辑
6 条分支只有 1 条会产生回复，其余为空。代码节点取非空值输出。

### 输入参数

| 参数名 | 来源 |
|--------|------|
| `output` | 分支①商品咨询LLM输出 |
| `output1` | 分支②洗护指南LLM输出 |
| `output2` | 分支③物流发货LLM输出 |
| `output3` | 分支④退换售后LLM输出 |
| `output4` | 分支⑤优惠活动LLM输出 |
| `output5` | 分支⑥其他兜底LLM输出 |

### 代码（Python）
```python
async def main(args: Args) -> Output:
    params = args.params
    outputs = [
        params.get('output', ''),
        params.get('output1', ''),
        params.get('output2', ''),
        params.get('output3', ''),
        params.get('output4', ''),
        params.get('output5', '')
    ]
    reply = ''
    for o in outputs:
        if o:
            reply = o
            break
    if not reply:
        reply = '抱歉，我这边暂时没接住这个问题～您回复「转人工」，我帮您转接人工客服。'
    return {'reply': reply}
```

### 输出
```
reply = 非空分支的回复内容（六路皆空时返回兜底文案）
```

## 七、结束节点

### 输出配置

结束节点有两种输出类型，**客服场景必须选「返回文本」**：

| 输出类型 | 表现 | 是否采用 |
|---------|------|---------|
| 返回变量 | 输出结构化 JSON，形如 `{"reply":"..."}` | ❌ |
| **返回文本** | 直接输出拼好的文本 | ✅ |

配置：
```
输出类型：返回文本
回答内容：{{reply}}
流式输出：开启
```

> ⚠️ **踩坑记录**：智能体切换到「对话流模式」后，对话流的输出会**原样透传**给用户。若结束节点用「返回变量」，用户会看到 `{"reply":"亲~..."}` 这样的代码；改成「返回文本」+ `{{reply}}` 后即为纯文本。
>
> 对比：在「自主规划模式」下，智能体的大模型会读取 reply 的值再组织语言，所以变量模式也看不出问题——这也说明模式切换时要重新验证输出形态。

## 九、会话记忆设计

对话流**原生绑定会话**，无需手工配置记忆变量：

| 能力 | 说明 |
|------|------|
| 历史消息读取 | 模型节点可读取本会话的历史消息，多轮追问自动带上上下文 |
| 上下文传递 | 会话上下文与用户问题一起传给大模型 |
| 记忆范围 | 由智能体侧的「携带上下文轮数」控制（本项目设为 10 轮） |

### 多轮对话示例
```
用户：1.5米的床选什么规格？
AI：亲~ 1.5米床建议选被套200×230cm的规格...

用户：那红色的有吗？          ← 对话流读取历史，知道在问 1.5 米床品
AI：亲~ 1.5米床品套件有经典白色和雾霾蓝可选...

用户：多少钱？                ← 继续引用同一商品
AI：亲~ 1.5米四件套参考价299-599元...
```

> 对比：工作流模式下必须靠人设 Prompt 手工补全问题，对话流模式下这段逻辑可以删掉。

## 十、角色配置（对话流专属）

对话流支持独立的角色配置，用于发布到 Chat SDK / 绑定 AI 对话组件时展示：

| 字段 | 内容 |
|------|------|
| 角色名称 | 优眠小助手 |
| 角色描述 | 优眠家居官方智能客服，解答床品咨询，支持商品推荐、洗护指南、物流查询、退换货 |
| 角色头像 | 床品/枕头图标 |

## 十一、在扣子中的搭建步骤

### 11.1 创建与转换
1. 方式一：资源库 → 创建工作流 → 在操作列选择**切换为对话流**
2. 方式二：资源库 → 创建 → 直接创建对话流
3. 名称：`customer_service_workflow`

### 11.2 添加节点

| 顺序 | 节点类型 | 名称 | 作用 |
|------|---------|------|------|
| 1 | 选择器 | 意图识别 | 把用户消息分成 6 类（自带 LLM） |
| 2 | LLM × 6 | 各分支回复 | 每个分支挂载知识库并生成回复 |
| 3 | 代码 | 代码 | 合并 6 路输出并格式化 |
| 4 | 结束 | 结束 | 输出 reply |

### 11.3 连线
```
开始 → 意图识别
            ├→ 商品咨询回复 ──┐
            ├→ 洗护指南回复 ──┤
            ├→ 物流发货回复 ──┤
            ├→ 退换售后回复 ──┼→ 代码 → 结束
            ├→ 优惠活动回复 ──┤
            └→ 其他兜底回复 ──┘
```

### 11.4 关键检查项（转换后必做）

| 检查项 | 说明 |
|--------|------|
| 意图识别 `query` | 必须绑定 `开始.USER_INPUT`，不能是空的 `user_message` |
| 6 个 LLM 节点 `input` | 同上，全部绑定 `开始.USER_INPUT` |
| 代码节点输入 | 6 个参数分别对应 6 个 LLM 节点的 `output` |
| 结束节点输出 | 输出类型选**返回文本**，回答内容填 `{{reply}}` |

> ⚠️ 从工作流切换为对话流后，原绑定的 `user_message` 会变成非必填、值为空。若不改绑，意图识别会拿到空字符串，导致路由全错（实测表现为"问洗护却返回物流"）。

### 11.5 测试对话流
搭建完成后，点「试运行」→「保存并开始对话调试」，用对话方式输入测试用例：

| 测试输入 | 期望分支 | 期望结果 |
|---------|---------|---------|
| "你好" | ⑥其他兜底 | 返回开场白 |
| "你们有什么商品推荐？" | ①商品咨询 | 推荐具体商品+价格 |
| "纯棉床品怎么洗？" | ②洗护指南 | 分步骤洗护说明 |
| "什么时候发货？" | ③物流发货 | 48小时内发货 |
| "我要退货" | ④退换售后 | 7天无理由退货流程 |
| "有没有满减？" | ⑤优惠活动 | 当前活动说明 |
| "能便宜点吗？" | ⑤优惠活动 | 引导领券/说明活动价（议价本身不接，但会落到优惠活动分支回答） |
| "1.5米的床选什么？" | ①商品咨询 | 尺寸推荐 |
| "红色的有吗？" | ①商品咨询 | 颜色推荐（多轮，靠会话记忆） |
| "那多少钱？" | ①商品咨询 | 价格说明（多轮，靠会话记忆） |
| "我要投诉" | ④退换售后 | 引导转人工 |

> 试运行面板以 JSON 形式展示输出变量（形如 `{"reply":"..."}`），其中的 `\n` 是换行转义。这只是调试视图，最终用户看到的是纯文本。

### 11.6 发布
点右上角「发布」，填写版本号与描述后确认。发布后的对话流可被智能体引用，也可直接发布到 API&SDK、小程序、社交渠道等。
